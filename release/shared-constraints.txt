# One source of truth for every distribution that more than one release lock
# graph resolves. All four `.in` graphs are compiled against this file, so the
# locks cannot disagree about a shared distribution: they are constrained to the
# same row rather than being pinned twice and hand-matched afterwards.
#
# Reciprocal `==` pins across two locks are what drifted before: certifi reached
# 2026.6.17 in tooling and 2026.7.22 in attestation, which made the combined
# `pip install --require-hashes` in release.yml a ResolutionImpossible. A third
# hand-matched pin would only queue up the next divergence.
#
# Rules enforced by `release_artifacts.py audit-locks`:
#   * every distribution present in two or more release locks appears here;
#   * every row here matches the version those locks resolved;
#   * no release lock resolves one distribution at two different versions;
#   * every exact root in a `.in` graph agrees with its row here.
#
# Editing a row here moves that distribution in every lock at once. Regenerate
# with the exact command recorded in each lock header afterwards.
